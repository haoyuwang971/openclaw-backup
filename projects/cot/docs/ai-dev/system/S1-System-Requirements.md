## 1. 需求概述

本文档定义 **Cot EMS 系统** 的系统级需求。系统级需求与软件级需求的区别在于：

- **系统需求**: "系统（含EMS控制器+所有连接设备）必须满足什么"
- **软件需求**: "EMS控制器中的软件必须实现什么"

### 1.1 需求编号规则

| 层次 | 前缀 | 编号示例 | 说明 |
|------|------|---------|------|
| 系统需求 | **SR** | SR-001 | System Requirement，由利益相关者直接提出 |
| 软件需求 | **FR** | FR-001 | Functional Requirement，由系统需求派生 |
| 约束 | **SC** | SC-001 | System Constraint，设计约束/物理约束 |

## 2. 系统功能需求 (System Functional Requirements)

### 2.1 能量管理域

#### SR-001 绿电最大化消纳
> **需求**: 系统在并网状态下，应优先利用光伏发电供给负载，多余电量存入储能，光伏不足时由储能补充，最小化从市电购电。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：模拟光伏充足/不足场景，测量关口表购电功率 |
| **验收标准** | 光伏充足时关口表功率 ≤ 5kW（防逆流余量）；光伏不足时PCS放电功率 ≥ 缺口×95% |
| **追溯** | → FR-001 (绿电消纳策略), FR-002 (备电恢复策略) |
| **利益相关者** | STK-02 (能源管理专员), STK-05 (市电电网) |

#### SR-002 离网供电保障
> **需求**: 系统在市电中断时，应在500ms内切换至离网模式，由储能通过PCS向负载供电，保障重要负载不间断。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：断开市电，示波器测量负载电压跌落 |
| **验收标准** | 切换时间 ≤ 500ms；负载电压跌落 < 10%；重要负载不停机 |
| **追溯** | → FR-003 (并离网切换), FR-004 (并柴发切换) |
| **利益相关者** | STK-07 (交流负载), STK-01 (现场运维) |

#### SR-003 柴发应急备用
> **需求**: 系统在离网模式下，当储能SOC降至20%时，应自动启动柴油发电机；当SOC恢复至80%或市电恢复时，应停止柴发。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：模拟离网+SOC下降场景，验证柴发启停逻辑 |
| **验收标准** | SOC ≤ 20%时3s内发出启动信号；柴发启动后30s内并机成功 |
| **追溯** | → FR-004 (柴发联动), FR-005 (SOC边界保护) |
| **利益相关者** | STK-06 (柴油发电机), STK-07 (交流负载) |

#### SR-004 簇间SOC均衡
> **需求**: 系统应维持两簇电池SOC的一致性，当簇间SOC差值超过阈值时，通过功率分配调节实现均衡。

| 属性 | 内容 |
|------|------|
| **优先级** | Should |
| **验证方法** | 现场测试：人为制造SOC差异，观察功率分配调节 |
| **验收标准** | 簇间SOC差值 ≤ 5%（可调） |
| **追溯** | → FR-006 (簇间SOC一致) |
| **利益相关者** | STK-02 (能源管理专员) |

### 2.2 安全保护域

#### SR-005 防逆流保护
> **需求**: 系统在并网运行时，应防止功率向电网倒送（逆流），当检测到逆流趋势时，应调节PCS功率消除逆流。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：模拟光伏过剩场景，测量关口表功率方向 |
| **验收标准** | 关口表功率始终 ≥ -5kW（可设置余量）；检测-响应周期 ≤ 200ms |
| **追溯** | → FR-007 (防逆流保护), FR-008 (需量保护) |
| **利益相关者** | STK-05 (市电电网) |

#### SR-006 需量控制
> **需求**: 系统在并网充电时，应从电网吸收的功率不超过设定需量上限，避免触发电网需量惩罚。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：设定需量上限，验证充电功率约束 |
| **验收标准** | 电网侧功率 ≤ 需量设定值；超限时PCS充电功率线性降载 |
| **追溯** | → FR-008 (需量保护) |
| **利益相关者** | STK-05 (市电电网), STK-02 (能源管理专员) |

#### SR-007 储能边界保护
> **需求**: 系统应防止储能过充（SOC > 95%）和过放（SOC < 20%），接近边界时限制充放电功率。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：模拟SOC边界条件，验证功率限制 |
| **验收标准** | SOC ≥ 95%时禁止充电；SOC ≤ 20%时禁止放电（并离网逻辑不同） |
| **追溯** | → FR-005 (SOC边界保护), FR-009 (故障保护停机) |
| **利益相关者** | STK-03 (BAM电池管理) |

#### SR-008 故障安全停机
> **需求**: 系统检测到L1/L2级故障时，应立即停机保护；检测到急停信号时，应在100ms内切断所有功率输出。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：触发急停/模拟故障，测量响应时间 |
| **验收标准** | 急停响应 ≤ 100ms；L1故障响应 ≤ 200ms；停机后所有PCS待机 |
| **追溯** | → FR-009 (故障保护停机), FR-010 (故障检测) |
| **利益相关者** | STK-01 (现场运维), STK-07 (交流负载) |

### 2.3 状态切换域

#### SR-009 并离网自动切换
> **需求**: 系统应自动检测市电状态，实现并网/离网模式的平滑切换；切换过程负载电压波动不超过10%。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：模拟市电掉电/恢复，测量切换时间和电压 |
| **验收标准** | 市电掉电→离网：≤ 500ms；离网→并网：≤ 2s；电压波动 < 10% |
| **追溯** | → FR-003 (并离网切换), FR-011 (系统状态监测) |
| **利益相关者** | STK-05 (市电电网), STK-07 (交流负载) |

#### SR-010 并柴发切换
> **需求**: 系统应支持从离网模式切换至并柴发模式；柴发启动稳定后自动并机，柴发停机前自动解列。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：模拟SOC下降至20%，观察柴发启停全流程 |
| **验收标准** | 柴发启动信号发出后30s内并机；柴发停机前PCS先降载至0 |
| **追溯** | → FR-004 (并柴发切换), FR-012 (柴发状态监测) |
| **利益相关者** | STK-06 (柴油发电机), STK-07 (交流负载) |

### 2.4 数据采集与通信域

#### SR-011 多协议设备接入
> **需求**: 系统应同时接入5台PCS、7台MPPT、2台BAM、4块电表、1台STS、4台液冷机，支持Modbus-RTU/TCP协议。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：所有设备同时在线，通信成功率统计 |
| **验收标准** | 23台设备同时在线；单设备通信周期 ≤ 2s；通信成功率 ≥ 99.5% |
| **追溯** | → FR-013 (设备接入), FR-014 (协议转换), FR-015 (数据缓存) |
| **利益相关者** | STK-01 (现场运维), 所有设备 |

#### SR-012 断点续传
> **需求**: 系统在与云端通信中断时，应在本地缓存数据；通信恢复后自动补发断网期间的数据。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：断开WAN网络，恢复后检查数据完整性 |
| **验收标准** | 本地缓存 ≥ 7天数据；断网期间数据不丢失；恢复后24h内补发完成 |
| **追溯** | → FR-016 (断点续传) |
| **利益相关者** | STK-03 (云端管理员) |

#### SR-013 设备心跳监控
> **需求**: 系统应监控所有关键设备的心跳状态，设备通信超时后判定故障并触发告警。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：断开某设备通信，观察故障判定时间 |
| **验收标准** | PCS心跳周期 ≤ 5s；BAM心跳周期 ≤ 10s；连续3次超时判定故障 |
| **追溯** | → FR-010 (故障检测), FR-017 (告警分级) |
| **利益相关者** | 所有设备, STK-01 (现场运维) |

### 2.5 人机交互域

#### SR-014 本地监控
> **需求**: 系统应提供本地触摸屏界面，显示实时数据、系统状态、告警信息，支持手动控制模式切换。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：操作HMI验证所有功能 |
| **验收标准** | 7寸屏显示；数据刷新周期 ≤ 2s；手动切换响应 ≤ 1s |
| **追溯** | → FR-018 (本地HMI), FR-019 (Web监控) |
| **利益相关者** | STK-01 (现场运维) |

#### SR-015 远程监控
> **需求**: 系统应通过MQTT/HTTPS向私有云平台上报遥测数据，接收远程指令和策略配置。

| 属性 | 内容 |
|------|------|
| **优先级** | Must |
| **验证方法** | 现场测试：验证数据上报和指令下发 |
| **验收标准** | 遥测上报周期 ≤ 30s；指令下发响应 ≤ 5s；TLS加密传输 |
| **追溯** | → FR-019 (Web监控), FR-020 (远程指令), FR-021 (用户权限) |
| **利益相关者** | STK-03 (云端管理员), STK-02 (能源管理专员) |

## 3. 系统约束 (System Constraints)

### 3.1 物理约束

| ID | 约束 | 说明 | 来源 |
|----|------|------|------|
| **SC-001** | 控制器供电: DC12V~48V | 柴发启动时电压可能跌落 | 硬件规格 |
| **SC-002** | 工作温度: -20°C ~ +60°C | 缅甸热带环境 | 硬件规格 |
| **SC-003** | 通信接口: RS485×8 + 以太网×6 | 最多接入23台设备 | 硬件规格 |
| **SC-004** | 控制周期: ≤ 100ms | 状态机扫描周期 | 实时性要求 |
| **SC-005** | 直流侧功率平衡: P_bat = P_pv - P_clu/η | 物理定律约束 | 电气工程 |

### 3.2 环境约束

| ID | 约束 | 说明 | 来源 |
|----|------|------|------|
| **SC-006** | 太阳辐照不可控 | 光伏发电量随天气变化 | 自然环境 |
| **SC-007** | 市电质量不稳定 | 弱电网，电压/频率波动大 | 缅甸电网 |
| **SC-008** | 柴发冷启动时间 | 从启动到稳定输出 ≥ 30s | 柴油发电机特性 |

### 3.3 法规约束

| ID | 约束 | 说明 | 来源 |
|----|------|------|------|
| **SC-009** | 防逆流合规 | 并网运行时不得向电网送电 | 电网法规 |
| **SC-010** | 电能质量 | 输出电压/频率满足当地标准 | 缅甸电力标准 |

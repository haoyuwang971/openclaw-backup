## 关键概念澄清

### 系统 (System) vs 软件 (Software)

| 维度 | 系统级 (SysML) | 软件级 (UML) |
|------|---------------|-------------|
| **边界** | WL-EMS-1000-M 控制器 + 23台设备 + 电气拓扑 | EMS控制器内部软件模块 |
| **能量流** | 光伏→直流母线→电池/PCS (物理能量) | 数据采集→策略计算→指令下发 (信息) |
| **组成** | 硬件(PCB/CPU/通信板) + 软件(固件/APP) + 设备 | 进程/线程/模块/类 |
| **约束** | 功率平衡方程、电气额定值、热设计 | 内存限制、实时性、协议格式 |

## 使用指南

### 对系统工程师（或你自己review时）
1. 从 **S0** 开始 → 理解系统边界和利益相关者
2. 读 **S1** → 确认系统需求及其验收标准
3. 读 **S2** → 理解系统由哪些模块组成、端口如何连接
4. 读 **S3~S5** → 理解系统行为、物理约束、功能分配

### 对软件工程师
1. 从 **S1** 的系统需求出发，追溯到 **[software/01-PRD.md](../software/01-PRD.md)** 的软件需求
2. 读 **[software/03-Architecture.md](../software/03-Architecture.md)** → 理解软件5层架构
3. 读 **[software/04-State-Machine.md](../software/04-State-Machine.md)** 与 **[software/05-Functional-Spec.md](../software/05-Functional-Spec.md)** → 理解状态机和功能逻辑
4. 读 **[software/11-结构化分析方法.md](../software/11-结构化分析方法.md)** 与 **[software/12-面向对象建模方法.md](../software/12-面向对象建模方法.md)** → 从DFD和UML两种视角理解软件逻辑

### 对项目经理
1. **S0~S2** 用于和客户确认系统范围和验收标准
2. **[software/00~09](../software/)** 用于开发团队的任务拆分和进度跟踪
3. **S5-Allocation** 用于识别硬件采购和软件外包边界
